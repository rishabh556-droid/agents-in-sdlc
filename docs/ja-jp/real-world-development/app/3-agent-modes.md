プロジェクトに小さな機能を追加しました。より大きな変更には、さらにしっかりしたプロセスが必要です。GitHub Copilot app は組織の既存のワークフローに沿って動作し、適切なものを適切な方法で構築できるように設計されています。このレッスンから数回にわたり、一般的なエージェント駆動の開発プロセスに従います。まず issue を使って新機能を作成し、コードが有効で、機能が期待どおりに動作することを確認し、最終的にプロジェクトへ正常にマージします。

> [!NOTE]
> 機能のワークフローを続ける間、同じセッションを使います。通常はファイルの種類ごとに異なるセッションや PR を使いますが、ここでは主な概念に集中するため手順を簡略化します。

このレッスンでは、次のことを行います。

- GitHub issue から新しいエージェント セッションを始めます。
- **Plan** モードで要件を決めます。
- **Autopilot** モードで新機能を実装します。
- コードをレビューします。
- ブラウザー キャンバスで機能を手動検証します。

機能の作成を続ける中で、リポジトリの指示を更新し、既存の quality-checks スキルをカスタマイズして、MCP による検証を追加し、QA エージェントを作成し、機能の PR を開きます。

## シナリオ

Tailspin Toys のカタログが増え、利用者はカテゴリや publisher でゲームを絞り込みたいと考えています。バックログの issue には機能が記載されていますが、カテゴリを組み合わせる方法など、コーディング前に合意が必要な詳細もあります。Plan モードで決定し、Autopilot による範囲を明確にした実装を承認します。

## 背景

開発ワークフローに AI コーディング エージェントを導入しても、基本は変わりません。むしろ、基本がさらに重要になります。多くの開発者は、次のような流れで作業します。

1. 実施内容を記載した issue を開きます。
2. 実装する内容を計画します。
3. コードを作成してレビューします。
4. テストを実行してコードを検証します。
5. 新機能を手動で検証します。
6. プルリクエスト (PR) を作成します。
7. コードのレビューと継続的インテグレーション プロセスが成功したら、コードをマージします。

> [!NOTE]
> 詳細な手順はチームや組織によって異なりますが、通常は上記の流れを基にしています。

この標準的な進め方に従うことで、AI が生成したコードが要件を満たし、手作業で書いたコードと同じレビュー プロセスを通るようにできます。

## セッション モード

**セッション モード**は、エージェントに与える自律性の範囲を制御します。プロンプト フィールド下のドロップダウンで設定でき、いつでも変更できます。

- **Interactive**: エージェントと一緒に作業します。エージェントは変更を提案し、次の作業に進む前にユーザーの応答を待ちます。
- **Plan**: エージェントが最初に計画を作成します。実行前に計画をレビューして承認します。
- **Autopilot**: エージェントが自律的に作業します。ユーザーの入力を待たずに、コードの作成、テストの実行、反復を行います。

まず Plan モードで計画を作成してレビューし、その後 Autopilot モードで実装します。

## Issue からセッションを開始する

作業を始める前に、星評価の PR がマージ済みで、ローカルの `main` が最新であることを確認します。

1. サイドバーの **Sessions** で Tailspin Toys リポジトリ フォルダーを選択し、リポジトリ上部のナビゲーションで **Issues** を選択します。**Allow users to filter games by category and publisher** を開きます。これはテンプレートに含まれる issue です。新たに作成する必要はありません。
2. **New session** を選択し、更新済みの `main` に基づく **new working tree** を選びます。

    ![GitHub Copilot app の issue ビューで New session ボタンを矢印で示した画面](../../../_images/app-new-session-from-issue.png)

3. issue がセッションに添付されていることを確認し、モード選択メニューで **Plan** を選択します。

> [!NOTE]
> Node.js または npm が見つからない場合は、エージェントに `node --version` と `npm --version` の実行を依頼します。ターミナルでは動作するのにセッションで動作しない場合は、アプリの PATH またはバージョン マネージャーの設定を確認し、アプリを完全に終了してから再起動します。失敗した操作とチェックを再試行してください。エージェントが npm を見つけられないという理由だけで再インストールしないでください。

## フィルター機能を計画する

計画を立てると、Copilot がコードを書く前にアプローチをレビューできます。issue から開始したため、Copilot はすでに機能の要望をコンテキストとして把握しています。次の内容を送信します。

```plaintext
Build this feature.
```

Copilot の質問に回答し、issue の受け入れ条件と計画を照らし合わせます。カテゴリと publisher による絞り込み、アクセシブルなコントロール、データ アクセスの変更、テストが含まれていることを確認します。複数カテゴリの組み合わせ方法や、該当するゲームがない場合の動作など、明確でない部分を話し合います。

計画には、プロジェクトの既存ツールを使った lint、ユニット テスト、E2E テスト、型チェックを含めます。フィルター機能の実装とテストに範囲を絞り、品質ワークフローが完了してから PR を作成します。承認前に計画の修正を依頼し、後の検証に使えるよう issue の URL と合意した追加事項を控えます。

## Autopilot を明示的に承認する

計画に納得できたら **Approve and implement this plan**、または使用中のバージョンに表示される同様の選択肢を選びます。承認するとモードも切り替わると決めつけず、現在のモードを確認します。モード表示が **Autopilot** になっていることを確認してください。

Copilot が実装を始めます。作成した計画に沿ってコードを生成し、テストを実行して作業を反復します。

> [!NOTE]
> 承認するとすぐに実装が始まる場合があるため、先に計画をレビューしてください。依存関係が見つからない、ポートが競合しているなどの報告があれば、チェック完了とみなす前にセットアップの問題を解決します。自分で起動したサーバーだけを停止してください。

## 実装をレビューして検証する

生成されたコードは、他のコードと同様にマージ前にレビューする必要があります。コードをレビューし、サイトを実行して問題がないか確認します。

1. **Changes** を開いて、フィルター機能の実装とテストを確認します。
2. 複数カテゴリと publisher の組み合わせも含め、結果を issue と承認済みの追加事項に照らし合わせます。変更が既存のリポジトリ指示に従っていることも確認します。
3. lint、ユニット テスト、E2E テスト、型チェックの出力を確認します。スキップされたチェックは成功ではありません。
4. 実装を承認する前に失敗を解消し、該当するチェックを再実行します。Playwright の E2E 設定はビルドしてプレビューを配信し、ローカル サーバーを再利用する場合があります。テスト対象が前のレッスンではなく、この worktree のサーバーであることを確認してください。

## 新機能を確認する

コードに問題がないように見えても、実際に動くでしょうか。前と同じようにアプリを起動し、ブラウザー キャンバスでサイトを開きます。

1. 次のプロンプトを使い、アプリを起動してブラウザー キャンバスで開くよう Copilot に依頼します。

    ```plaintext
    Start the app and open it in the browser canvas.
    ```

2. しばらくするとアプリが起動し、Copilot app 内にブラウザー ウィンドウが開きます。
3. カテゴリを選んで結果を確認します。フィルターを解除し、publisher を選んで、その publisher のゲームが表示されることを確認します。
4. カテゴリと publisher を組み合わせて、issue と承認した計画に沿った結果になることを確認します。複数カテゴリに対応している場合は、合意した組み合わせの動作も検証します。
5. 該当するゲームがない組み合わせを試し、空の状態を確認します。フィルターを解除またはリセットして、全ゲームの一覧が戻ることも確認します。
6. 確認が終わったら、次のプロンプトを使い、このセッションで起動した開発サーバーを停止するよう Copilot に依頼します。

    ```plaintext
    Stop the dev server and close the browser canvas.
    ```

## 次のレッスンのためにセッションを維持する

まだフィルター機能の PR を作成またはマージしないでください。レッスン 4 ～ 8 では、同じセッション、worktree、ブランチを維持します。次のレッスンでカスタム指示をフィルター機能のコードに適用し、スキルと QA の改善を加えてから、レッスン 8 で PR をまとめて作成してマージします。開発サーバーを停止した後、セッションはそのままにしておきます。次のレッスンで同じセッションに戻ります。

- **Plan** モードで要件を決めました。
- **Autopilot** モードで新機能を実装しました。
- コードをレビューしました。
- ブラウザー キャンバスで機能を手動検証しました。
