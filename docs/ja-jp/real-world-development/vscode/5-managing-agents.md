GitHub Copilot をエージェント モードで使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行を自律的に行います。VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集がリアルタイムで表示されます。差分をインラインで確認し、個々の変更を承認または却下できます。エディターを離れずに追加のプロンプトで会話を誘導し、作業を調整・拡張できます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイルの編集をレビューして承認します。
- セッションの途中でエージェントに指示を加え、高コントラスト モードにライト モードの切り替え機能を追加します。

## シナリオ

[演習 4][previous-lesson] で使ったアクセシビリティ カスタムエージェントが、高コントラスト モードを実装しています。作業中にデザイン チームから追加の要望がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライト モードの切り替えも追加してほしいとのことです。新しい会話を始める代わりに、現在のセッションに指示を加えて作業を広げます。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調査するファイル、実行するコマンド、提案する編集が示され、ファイルの差分には **Keep** と **Undo** の操作が表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツール呼び出しを確認します。ファイルの読み込みや編集、実行を求められたターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案したら、差分を確認します。
   - **Keep** を選択すると変更を承認します。
   - **Undo** を選択すると変更を取り消し、エージェントに別の方法を試させます。
4. チャット上部の **Files changed** を開き、このセッション中にエージェントが変更したファイル全体を確認することもできます。

> [!NOTE]
> ターミナル コマンドの実行などでツールの許可を求められると、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントが高コントラスト モードの実装を終えるまで待ちます。最後に、変更内容の概要が表示されます。

## エージェントにライト モードを追加するよう指示する

高コントラスト モードができたので、同じ会話でライト モードの切り替え機能を追加します。同じチャット セッションを続けるため、エージェントはこれまでの作業、変更したコンポーネント、スタイルの方針、local storage を使った設定の保存方法を把握しています。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を調べ、ライト モードの追加を提案します。
3. 新しい編集を確認します。高コントラスト モードのときと同じように、差分ごとに **Keep** または **Undo** を選択します。
4. エージェントの方向性が希望と異なる場合 (たとえば切り替え UI を意図しない方法でリファクタリングする場合) は、入力欄の隣にある **Stop** を選択して停止し、明確な追加プロンプトを送信します。

> [!TIP]
> 作業中のセッションを誘導すると、最初から会話を始めるよりも早く調整できます。追加プロンプトを使って、調整を依頼します (「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」)、軌道を修正します (「トグルを 3 つにせず、ライト モードを既存の設定パネルに追加する」)、または範囲を広げます (「両方のトグルにキーボード ショートカットも追加する」)。

## 変更ファイルをレビューする

コミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントが示したアクセシビリティ パターン (ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保存) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージングしてコミットします。次のレッスンで公開します。

## まとめと次の手順

Copilot Chat のエージェント モードを使い、進行中のセッションを監視して指示を追加しました。ファイル編集を確認し、変更を承認または却下し、コンテキストを保ったまま追加プロンプトで作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を承認または却下しました。
- 追加プロンプトで進行中のセッションを誘導しました。
